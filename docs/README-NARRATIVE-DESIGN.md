# README narrative design

The public README combines two responsibilities:

1. explain why PDC matters to a Product Owner;
2. provide the operational and governance information expected from an open-source project.

Future release work must integrate these responsibilities rather than replacing the product narrative with a release checklist. Quick Start, license, verification, security, contribution, release, and Public/Private boundary sections are necessary, but they do not substitute for the human problem, PDC/Coding Agent distinction, responsibility split, concrete examples, and intended users.
